## 1. 概述、目标与非目标

### 1.1 一句话
把现有「南宁街头」开放城区**收成一条可吃、可砸、可骑的中山路美食街（约 300m）**：可进店嗦粉、可搬凳砸铺，被老板追、被电单车巡警追；主角与服装数据驱动可换。

### 1.2 必须做到（按可玩里程碑，不是一次做完）

**M1 — 可逛（PR2 末，对外试玩门槛）**
1. 单街 z ∈ [−150, +150]，街面 9m + 两侧廊下 2.4m；Phase A 店铺可进入（四类必做：老友粉、粉饺、烧烤/生蚝、奶茶）。
2. 走 / 慢跑 / 冲刺 / 跳（在现有 `Player` 跳跃上补体力、蹲、台阶高度）。
3. 进店 → 简易点餐（菜品 + 少许选项）→ 付款 → 吃 → 饱腹/基础 Buff。
4. 旧整店砸铺仍可用；街内无 AI 汽车；电单车可骑（可先用现 `dianche`）。
5. 桌面 60fps（中段夜景机位）；核心纯规则有单测；smoke + 基础 e2e 绿。

**M2 — 可活（PR3+PR4）**
6. 共享单车开锁/计费/还车；电单车调参 + 人流限速。
7. 街上有人：老板/摊主/食客/路人按时段走动，白话气泡（≥40 句先上，80 句为目标）。
8. 线性小地图、第一次进店教学、本地进度。

**M3 — 可砸（PR5a，对外「完整竖切」）**
9. 道具可拿/扔/打碎（运动学 + Debris）；店铺分部件；老板劝→骂→追/报警；步行+电单车巡警；赔偿与口碑；每日 06:00 复原。

**M4 — 增强（PR5b，可选）**
10. cannon-es 活跃刚体；完整吃霸王餐/后付；辣度表与完整 Buff 叠乘。

### 1.3 非目标（本期明确不做）
- 不做中山路以外可玩街区（朝阳路、兴宁路、水街、邕江、大桥、机械厂、金狮/银狮巷）。**代码用旗标关掉生成与任务引用，文件暂留。**
- 不做街内汽车驾驶与 AI 车流、车载电台玩法（电台模块可留，运行时不挂）。
- 不做多人、云存档、1:1 测绘、骨骼 glTF 角色、主角/NPC 刚体物理。
- 不做血腥、真实 Logo/门头图复制、真实支付。
- 手机不做「一等公民」60fps 同等 NPC——见 §16 已锁定决策。

### 1.4 术语

| 术语 | 含义 |
|---|---|
| 骑楼廊下 | 首层退让有顶人行廊，宽 2.4m，比街面高 0.15m |
| 门面 / 铺 | 可进入的首层店铺单元 |
| 摊位 | 夜市流动摊，18:00（游戏时）后出摊 |
| Phase A / B | 内容填充档：A≈20 店+12 摊；B=36 店+24 摊 |
| Heat | 0–100，`starsFromHeat = ceil(heat/20)`，0–5 星 |
| 口碑 | 全街 −100…+100；另有每店拉闸/ban |
| 旗标禁用 | 代码路径保留，默认不进入玩法图 |

## 4. 架构

### 4.1 硬约束（不变）
- 模拟核心 **禁止** import `three`；`*.test.ts` 只测纯模块。
- 输入只经 `Controls`；碰撞查询权威是 `SpatialGrid`（扩展后仍保持 `resolve` 等价测试）。
- 固定步长 60Hz：`update` 模拟、`render` 表现。
- **少依赖**：不引入美术资源管线；cannon-es 仅 PR5b 且动态 import 分包。

### 4.2 模块策略（相对 v1.0）

| 策略 | 做法 |
|---|---|
| 删除 → **旗标** | `bootstrap`：`nanningStreetOnly=true` 时不生成旧区域、不挂 Radio、车流 0；`?stream=1` 仍可进旧路径（dev） |
| `main.ts` 拆分 | **PR0 单独做**，行为不变；目标 `main.ts` 只 bootstrap |
| 新纯模块 | `core/GameClock`、`nanning/street/*`、`player/*`（从 Player 抽）、`app/wanted` 等按 PR 表 |
| 角色 | 在现有 `render/character.ts` 上抽数据；不要并行第二套人体 |
| 物理 | PR5a：`PropSystem` + `NullPhysics`/运动学；PR5b：`CannonAdapter` |

### 4.3 依赖方向（同 v1.0，略）

```
render/ui  ──只读快照──▶  app(bootstrap, simStep, renderFrame)
                              │ step()
                         纯核心（player, street, dining, props, npc, wanted…）
```

写回只通过命令/事件；sim 内只用 `createRng(seed)`。

### 4.4 每帧顺序（目标；PR0 先搬移不改序）

1. `controls.sample()` → `InputFrame`（修 0-sim-步丢边沿：pendingEdges）
2. `clock.advance` → 营业/摊/dailyReset 事件
3. player / twoWheel / props / combat / consequences / police / npc / dining / buffs / bikeShare / wanted / missions
4. `eventBus` → 音效与 toast 排队
5. render：插值、pose、室内流式（每帧最多 1 间）、相机、灯、HUD（DOM 多 10Hz）

## 5. 街道规格（执行摘要）

完整常量以 `src/nanning/street/streetSpec.ts` 为准；数值沿用 v1.0 §3.1：

- 可玩段 z ∈ [−150, +150]；`roadHalfW=4.5`（街面 9m）；`arcadeDepth=2.4`；`arcadeRise=0.15`
- 三段：北粉店/粉饺、中夜市烧烤、南奶茶/螺蛳粉/便利
- 横巷东侧 z≈0：电单车停放 + 垃圾桶
- 南北口护栏 + 口外背景车车道；钟鼓楼在北口外背景

**碰撞**：PR2 引入 `Aabb3`（廊下 walkable、柱/墙 solid、卷闸动态）。车辆忽略 `maxY < 0.35` 的台面盒以便「颠上廊下」。

### 5.1 内容 Phase A（先做）

必做四类各至少 1 间真实核实或明确虚构：

| 优先级 | 示例 id（数据层） | 显示策略 |
|---|---|---|
| A 核实 | `benyuanyuan-laoyou`, `fuji-laoyou`, `zhongshan-fenjiao`, `aguang-doujiang`, `bingshen`, `hongjie-niuza`, `dawei-milktea`… | `fictional` 默认用 `fallbackName`；`real` 用真名 |
| 玩法必需虚构 | 1–2 家烧烤、1 家奶茶补位、1 便利店、凉茶/糖水 | 一直虚构 |
| 摊位 | 中段 12 个（东西各 6），品类含生蚝/酸嘢/炒螺/炸物 | 通用称呼 |

Phase B：按 v1.0 槽位表扩到 36+24；生成器一开始就按槽位预留填充门面，避免后期改碰撞。

### 5.2 店名与数据形状

```ts
export interface ShopDataRow {
  id: string;
  displayName: string;      // fictional 模式用这个
  realName?: string;        // 仅 verify A/B；real 模式且允许时用
  fallbackName: string;     // 与 displayName 可相同；C 级必填
  verify: 'A' | 'B' | 'C';
  sources: string[];
  kind: FoodKind;
  // section/side/slotZ/width/hours/interior/signColor/keeper/menuId…
}
```

构建期：`import.meta.env.VITE_SHOP_NAMES !== 'real'` → 全部走 `displayName`/`fallbackName`。  
README 固定声明：非官方、与商户无关；真名模式仅用于获得授权的演示包。

### 5.3 游戏时钟

```ts
realSecondsPerGameDay: 2880  // 默认；options 720–2880
startMinute: 17 * 60 + 30    // 17:30，夜市前
```

事件：06:00 `dailyReset`；17:30 摊车就位；18:00 开摊；02:00 收摊。  
人流系数沿用 v1.0 表，但 **环境 NPC 上限** 桌面 40（Phase A）/ 60（Phase B），手机 25。

### 5.4 室内

PR2 只做四模板：`laoyou` / `fenjiao` / `bbq` / `milktea`。  
其余模板 PR4。流式：30m 生成 / 40m 回收，每帧最多 1 间；手机 20/28、同时≤4。

## 7. 玩家控制器与碰撞

在现有 `Player`（已有 jump/coyote/airControl）上抽纯 `stepPlayer`：

| 项 | 目标（PR2） |
|---|---|
| 速度 | walk 1.6 / jog 4.2 / sprint 7.5 |
| 体力 | staminaMax 100；冲刺消耗；归零后回 25 才能再冲 |
| 跳 | 高度 ≈0.75m；与现实现校准，单测固定误差带 |
| 蹲 | C 切换；高度 1.15 |
| 台阶 | `stepHeight` 0.30；廊下 0.15 可直迈 |
| 半径 | 0.35（进店） |
| 碰撞 | `groundHeightAt` + `resolveCapsule`；凳 0.45 / 桌 0.75 / 高桌 1.05 可上；护栏 1.1 不可 |

相机：街 `distance≈5.5`、室内 ≈3.2；Pointer Lock；`segmentHitAabb3` 收回。醉意晃动选项可关（PR4+）。

## 9. 吃嘢（分期）

### 9.1 MVP（PR2 简易 / PR4 补全流程）— 先做这个

```
None → 门口 E → Menu（选 1 个菜 + 可选辣度/甜度）→ 扣款
    → Waiting(3–6s) → E 在座位旁坐下（或站立吃饮品）
    → Eating → Buff/饱腹 → None
```

- 单一 `DiningSession`；先付；钱不够拒绝。
- Buff 先做：`laoyou` 体力回复×1.6、`milktea` 冲刺×1.1、吃东西加饱腹；糖水清辣（若尚未做辣度表则只加饱腹）。
- **不做**：后付、霸王餐、咳嗽辣度 UI、口碑变价（口碑系统 PR5 再接）。

### 9.2 Full（PR5）
恢复 v1.0 状态机：后付烧烤、Owing/DineAndDash、spiceMeter、完整 Buff 表、满座提示与外带。

### 9.3 满座 UX（PR4 最小）
- 无空位：toast「位满啦，外带？／等一等」；允许外带（站立吃，无座位动画）。
- NPC 预约座位：玩家不能抢 `reservedBy`；超时 120s 释放。

- `PropDef` / `PropSystem`：拿、放、扔（解析抛物线 `predictArc`）、挥；命中用胶囊/射线，**不跑刚体岛**。

- 店铺分部件（玻璃柜/招牌/灯箱/柜台/霓虹…）；招牌可变成可搬道具。
- `NullPhysics` 仅测激活/休眠/记账。

### 10.3 PR5b（可选）
- `cannon-es` 动态 import；活跃≤60/25；超预算降级回运动学。
- 规则判定仍不依赖刚体落点（赔偿按事件）。

## 11. 后果、警察、口碑
